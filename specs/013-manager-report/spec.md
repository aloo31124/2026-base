## Clarifications

### Session 2026-08-02

- **議題**：公司總覽與兩張圖表的任務範圍。
  - **候選方案**：全部只統計主管建立的任務、全部統計同公司任務、總覽統計同公司而圖表統計目前主管建立的任務。
  - **採用方案**：公司摘要統計受派人屬於主管公司的所有任務；趨勢與狀態比例只統計目前主管建立的任務。
  - **採用理由**：同時符合「整個公司所有任務」及兩條圖表需求明載「自己指派出」的不同範圍。
  - **影響章節**：FR-003–FR-006、FR-010、FR-015。
- **議題**：「執行狀態」的定義。
  - **候選方案**：指派生命週期狀態、工作執行狀態、兩者混合。
  - **採用方案**：採 `待處理／進行中／已完成` 三種工作執行狀態。
  - **採用理由**：此分類最能回答任務執行進度，且與既有任務進度模型一致；退回與撤回仍保留在任務資料，不另創圖表分類。
  - **影響章節**：FR-008、FR-012–FR-014、Edge Cases。
- **議題**：執行者選項與日期邊界。
  - **候選方案**：公司全員或實際受派人；本曆年、最近 365 天或今日往前一年。
  - **採用方案**：執行者只列目前主管曾指派的對象；預設今日往前一年至今日，含首尾且最多 366 天。
  - **採用理由**：避免無關人員與空選項，並與既有系統報表時間契約一致。
  - **影響章節**：FR-007、FR-009、FR-016。
- **議題**：狀態篩選套用至圓餅圖時的呈現。
  - **候選方案**：圓餅圖忽略狀態篩選、只顯示選定狀態、移除圓餅圖狀態篩選。
  - **採用方案**：兩張圖共用同一組執行者、執行狀態與日期篩選；指定狀態時其餘狀態為 0。
  - **採用理由**：逐字符合兩條工作表需求均要求狀態篩選，且共用篩選可避免標籤切換後條件漂移。
  - **影響章節**：FR-008、FR-011–FR-014。

## User Scenarios & Testing

### User Story 1 - 檢視公司任務總覽 (Priority: P1)

主管可進入「主管報表」頁面，確認所屬公司名稱、所選期間公司任務總數與目前主管指派任務數。

**Why this priority**：這是主管辨識報表公司範圍及理解後續圖表口徑的入口。

**Independent Test**：以主管登入後開啟頁面，摘要只計入受派人屬於同公司的任務，不混入其他公司。

**Acceptance Scenarios**：

1. **Given** 主管具有公司綁定且公司內多人有任務，**When** 開啟主管報表，**Then** 顯示正確公司名稱與公司任務總數。
2. **Given** 另一家公司亦有任務，**When** 查詢主管公司摘要，**Then** 他公司任務不列入統計。

### User Story 2 - 檢視自己指派的任務趨勢 (Priority: P1)

主管可在「指派任務趨勢」標籤以折線圖查看自己指派任務的每日數量，並依執行者、執行狀態與時間範圍篩選。

**Why this priority**：工作表明確要求主管可分析自己的指派量變化，是主要報表價值。

**Independent Test**：建立多位主管、執行者、狀態與日期的任務後，任一篩選組合只回傳目前主管建立且符合條件的連續每日資料點。

**Acceptance Scenarios**：

1. **Given** 目前主管與另一主管皆建立任務，**When** 查看預設趨勢，**Then** 折線圖只統計目前主管指派的任務。
2. **Given** 任務分屬不同執行者與執行狀態，**When** 套用篩選，**Then** 摘要與資料點只包含符合全部條件的任務。
3. **Given** 首次進入頁面，**When** 未修改日期，**Then** 查詢範圍為今日往前一年至今日。

### User Story 3 - 檢視自己指派的任務狀態比例 (Priority: P1)

主管可在「指派任務狀態比」標籤以圓餅圖查看自己指派任務的待處理、進行中與已完成比例，並沿用相同篩選條件。

**Why this priority**：狀態分布可快速揭露工作阻塞與完成情況，且是工作表獨立 MUST 功能。

**Independent Test**：以三種執行狀態建立可預測資料，切換標籤後圓餅圖數量、百分比與篩選結果皆正確。

**Acceptance Scenarios**：

1. **Given** 目前主管指派的任務涵蓋三種執行狀態，**When** 開啟狀態比例標籤，**Then** 圓餅圖與文字圖例顯示各狀態數量及百分比。
2. **Given** 選定單一執行狀態，**When** 套用篩選，**Then** 選定狀態為全部結果，其餘狀態顯示 0。

### User Story 4 - 安全與例外狀態 (Priority: P2)

主管在載入中、無資料或服務失敗時可獲得清楚回饋；非主管無法存取頁面或 API。

**Why this priority**：報表必須避免洩漏公司資料或以空白畫面造成誤判。

**Independent Test**：非主管收到 403；無資料期間仍顯示零值資料與空資料提示；錯誤後可重新查詢。

**Acceptance Scenarios**：

1. **Given** 使用者沒有主管角色，**When** 存取主管報表，**Then** 頁面與 API 均拒絕並顯示模組專屬訊息。
2. **Given** 所選期間沒有符合任務，**When** 查詢完成，**Then** 趨勢補零、圓餅圖顯示全零且畫面說明沒有資料。

### Edge Cases

- 主管未綁定公司時回傳明確衝突訊息，不猜測公司範圍。
- 同公司中另一主管建立的任務只計入公司總覽，不計入目前主管的兩張圖表。
- 執行者不存在或從未接受目前主管任務時回傳 404，不回傳其他使用者資料。
- 起日與迄日相同時回傳單日資料點並含當日任務。
- 日期範圍最多 366 天；起日晚於迄日或超出上限時拒絕查詢。
- 執行狀態值不在允許清單時拒絕查詢。
- 日期切分採 `Asia/Taipei`，台灣凌晨任務不得落入前一日。

## Requirements

### Functional Requirements

- **FR-001**：系統 MUST 僅允許 `MANAGER` 角色存取主管報表頁面與 API。
- **FR-002**：主管報表頁面 MUST 顯示目前主管所屬公司名稱，且不得提供跨公司切換。
- **FR-003**：公司任務總數 MUST 只統計受派人綁定至目前主管公司的任務。
- **FR-004**：頁面 MUST 同時顯示所選期間的公司任務總數與目前主管指派任務總數。
- **FR-005**：「指派任務趨勢」MUST 只統計目前主管作為建立者的任務。
- **FR-006**：趨勢 MUST 以按日連續資料點的可存取折線圖呈現，無任務日補 0。
- **FR-007**：執行者篩選 MUST 提供「全部執行者」及目前主管實際指派過的對象，且不得洩漏其他使用者。
- **FR-008**：執行狀態篩選 MUST 提供「全部狀態」、`待處理`、`進行中`、`已完成`。
- **FR-009**：首次進入 MUST 預設查詢今日往前一年至今日，起迄日皆包含。
- **FR-010**：日期篩選 MUST 允許含首尾的 1 至 366 天範圍，起日不得晚於迄日。
- **FR-011**：趨勢摘要 MUST 顯示篩選後任務總數、公司任務總數、執行者範圍及日期範圍。
- **FR-012**：「指派任務狀態比」MUST 只統計目前主管作為建立者的任務並沿用相同篩選。
- **FR-013**：狀態比例 MUST 顯示待處理、進行中、已完成的任務數與百分比，總和為篩選後任務數。
- **FR-014**：圓餅圖 MUST 具有可存取名稱、文字圖例、狀態數量與百分比，零資料時提供明確提示。
- **FR-015**：兩個圖表標籤 MUST 共用篩選條件，切換標籤不得遺失已選條件。
- **FR-016**：所有報表日期 MUST 依 `Asia/Taipei` 日界線統計。
- **FR-017**：REST 回應 MUST 使用既有 `{ success, message, data, timestamp }` 格式並提供模組專屬錯誤訊息。
- **FR-018**：後端 MUST 依相關 DB 表、JPA DAO、Service、BO/DTO 與 REST Controller 分層。
- **FR-019**：前端 MUST 以 React page 與可重用圖表元件實作，沿用 `uiux/0.共用樣式` 的頁首、標籤、卡片、篩選與響應式流程。
- **FR-020**：功能 MUST 具 JUnit 整合測試、真實 HTTP Postman/Newman、React production build 與 Cypress E2E 證據及完成率報告。

### Key Entities

- **Company**：主管所屬公司與總覽範圍。
- **CompanyMembership**：使用者唯一公司歸屬，用於界定同公司任務。
- **AssignedTask**：包含建立者、受派人、指派時間、指派狀態與工作執行狀態的統計來源。
- **ManagerReportSource**：DAO 至 Service 的唯讀投影，包含時間、執行者與工作狀態。
- **ManagerReport**：公司摘要、套用篩選、連續趨勢點與狀態比例的唯讀回應。

## Assumptions

- 本次只處理「任務報表」第 18–20 列、狀態為「預計開發」的「主管報表」子模組；空白狀態的「我的報表」不在範圍。
- 不新增快照或彙總表；沿用 `company`、`company_membership`、`app_user` 與 `assigned_task` 即時查詢。
- 公司總覽與圖表以任務 `assignedAt` 作為日期來源；工作狀態以目前值統計，不建立歷史狀態快照。
- 退回或撤回任務仍是公司既有任務，依其目前工作執行狀態納入；不另創退回／撤回比例分類。
- 專案既有 JWT、角色、標準 API response 與錯誤處理機制持續沿用。

## Success Criteria

- **SC-001**：主管首次進入後可在 3 秒內看到公司摘要與最近一年兩種報表結果或明確空資料狀態。
- **SC-002**：公司總覽與目前主管指派任務的資料隔離正確率為 100%。
- **SC-003**：執行者、執行狀態與日期任意組合的篩選結果正確率為 100%。
- **SC-004**：折線圖日期資料點完整率為 100%，圓餅圖數量總和與篩選後任務數一致率為 100%。
- **SC-005**：非主管的頁面與 API 存取拒絕率為 100%，且不洩漏公司或人員資料。
- **SC-006**：所有規格、task、checklist、後端建置、前端建置、Postman 與 Cypress 驗收項目完成率為 100%。
